# Agent-Driven E2E Testing Platform

A production-grade E2E testing platform using Playwright, designed strictly for autonomous agents following Harness Engineering principles. This platform enforces **reliability over autonomy** by ensuring agents never hallucinate selectors, URLs, or test data.

---

## 🚀 How to Run the Tests Locally

You can run the generated Playwright tests locally just like any standard Playwright framework.

### 1. Installation

First, install the Node.js dependencies and the required Playwright browsers:

```bash
npm install
npx playwright install --with-deps
```

### 2. Execute Tests

Run the Playwright test suite (which includes the `ecommerce.spec.ts` generated by the Builder Agent):

```bash
npx playwright test
```

### 3. View the Reports

After execution, the platform outputs reports in two formats:
- **HTML Report:** 
  ```bash
  npx playwright show-report artifacts/execution-reports/html-report
  ```
- **Agent JSON Report:** The Runner Agent outputs a structured JSON report meant for the Debugger Agent at `artifacts/execution-reports/playwright-report.json`.

## 🤖 Practical Guide: How Agents Take Up Tasks

This repository is designed to be driven by an AI Orchestrator (e.g., AutoGen, LangChain, or a custom script). The orchestrator manages the lifecycle by passing structured JSON artifacts between four specialized agents.

Here is the step-by-step practical workflow of how a task is completed:

### Step 1: The Request
A human engineer requests a new test: *"Create an E2E test for adding a MacBook to the cart on our e-commerce site."*

### Step 2: The Explorer Agent
The Orchestrator wakes up the **Explorer Agent** and provides the target URL.
1. The Explorer Agent launches a headless browser.
2. It navigates the flow manually, capturing the DOM tree, accessible roles, and network requests.
3. It identifies valid locators (strictly following the `docs/selector-policy.md`).
4. **Handoff:** It generates `artifacts/exploration-reports/ecommerce-add-to-cart.json`.

### Step 3: The Builder Agent
The Orchestrator passes the exploration report to the **Builder Agent**.
1. The Builder Agent reads the JSON report. It is **forbidden** from guessing any selector not present in this file.
2. It generates Page Objects (`home-page.ts`, `product-page.ts`) mapping exactly to the Explorer's evidence.
3. It generates the Playwright spec (`ecommerce.spec.ts`) tracing every step back to the source URL and locator.
4. **Handoff:** It generates `artifacts/build-reports/ecommerce-build.json` to signal compilation success.

### Step 4: The Runner Agent
The Orchestrator triggers the **Runner Agent** (effectively executing `npx playwright test`).
1. The Runner acts as a strict execution engine. It does not modify code.
2. It captures videos, screenshots, and trace viewer logs.
3. **Handoff:** It outputs `artifacts/execution-reports/ecommerce-execution.json` containing the PASS/FAIL status and logs.

### Step 5: The Debugger Agent (If a test fails)
If the Runner Agent reports a failure, the Orchestrator passes the execution report to the **Debugger Agent**.
1. The Debugger Agent analyzes the trace logs and error messages.
2. If it identifies a simple data issue, it may propose a patch.
3. **Crucial Rule:** If it identifies that a DOM selector changed (e.g., the Cart button was renamed), it **refuses to hallucinate a fix**. Instead, it flags `REQUIRES_REEXPLORATION`.
4. The Orchestrator sees this flag and sends the task all the way back to **Step 2 (Explorer Agent)** to rediscover the new button safely.
5. If this loop repeats 3 times, the system triggers `ESCALATE_TO_HUMAN`.

## 📂 Project Structure Overview

The architecture forces a strict separation of concerns, mapping directories directly to agent responsibilities and execution phases.

```text
HarnessDrivenAutomation/
├── .github/
│   └── workflows/
│       └── agent-playwright-e2e.yml        # CI pipeline triggering Runner Agent & capturing artifacts
├── agents/                                 # Prompts & instructions governing agent logic
│   ├── builder-agent.md                    # Rule: Writes code strictly using evidence, no guessing
│   ├── debugger-agent.md                   # Rule: Analyzes failures; blocks hallucinated fixes
│   ├── explorer-agent.md                   # Rule: Navigates DOM, captures locators & state
│   └── runner-agent.md                     # Rule: Executes tests blindly, captures execution logs
├── artifacts/                              # Agent Memory: Passed JSON outputs
│   ├── build-reports/                      # Generated by Builder (Status & coverage)
│   ├── debug-reports/                      # Generated by Debugger (Failure categorizations)
│   ├── execution-reports/                  # Generated by Runner (Test results, traces)
│   └── exploration-reports/                # Generated by Explorer (DOM snapshots, validated locators)
├── docs/                                   # Policies the harness enforces
│   ├── escalation-policy.md                # 3-retry maximum loop before human escalation
│   ├── harness-guidelines.md               # Core "Reliability over Autonomy" principles
│   └── selector-policy.md                  # Strict ordering of locators (no XPaths, dynamic IDs)
├── orchestrator/                           
│   └── workflow.js                         # Example framework passing artifacts between agents
├── playwright/                             # Test Automation code
│   ├── config/
│   │   └── fixtures.ts                     # Setup for test context & data
│   ├── pages/                              # Generated Page Objects mapping to Explorer evidence
│   │   ├── cart-page.ts
│   │   ├── home-page.ts
│   │   └── product-page.ts
│   ├── tests/                              # Generated executable specs
│   │   ├── ecommerce.spec.ts
│   │   └── example.spec.ts
│   └── utils/
│       └── base-page.ts                    # The gatekeeper: Blocks illegal locators at runtime
├── schemas/                                # Validation logic for inter-agent communication
│   ├── build-report-schema.json
│   ├── debug-report-schema.json
│   ├── execution-report-schema.json
│   └── exploration-report-schema.json
├── package.json                            # Node.js project dependencies
└── playwright.config.ts                    # Playwright rules (timeouts, retry logic)
```

- **`/agents`**: Contains the core system prompts (markdown files) that govern AI behavior.
  - `explorer-agent.md`: Rules for the agent that navigates the DOM to collect evidence.
  - `builder-agent.md`: Rules for the agent that writes code strictly using the evidence.
  - `runner-agent.md`: Rules for the agent that executes the tests and captures logs.
  - `debugger-agent.md`: Rules for the agent that analyzes failures without hallucinating fixes.

- **`/schemas`**: Contains the JSON schemas validating the structured communication between agents.
  - `exploration-report-schema.json`, `build-report-schema.json`, `execution-report-schema.json`, `debug-report-schema.json`.

- **`/artifacts`**: The persistent memory and handoff layer. Agents do not use conversational chat memory; they read and write from these folders.
  - `/exploration-reports`: DOM evidence and verified locators.
  - `/build-reports`: Status of generated tests.
  - `/execution-reports`: Playwright test results (PASS/FAIL logs, traces, videos).
  - `/debug-reports`: Failure categorizations and escalation flags.

- **`/playwright`**: The actual executable TypeScript code generated by the Builder Agent.
  - `/pages`: Generated Page Object Models mapping to the exploration evidence (e.g., `home-page.ts`, `cart-page.ts`).
  - `/tests`: Generated executable specs tracing back to the exploration evidence (e.g., `ecommerce.spec.ts`).
  - `/config/fixtures.ts`: Custom state/auth setup for the tests.
  - `/utils/base-page.ts`: The gatekeeper class. It intercepts Playwright locators and throws runtime errors if forbidden selectors (like XPath) are used.

- **`/docs`**: The foundational rules that humans and agents must abide by.
  - `harness-guidelines.md`: The core "Reliability over Autonomy" principles.
  - `selector-policy.md`: The strict ordering of allowed locators (data-testid > role > text).
  - `escalation-policy.md`: The rule enforcing human escalation after 3 failures.

- **`/orchestrator`**
  - `workflow.js`: A conceptual script demonstrating how a framework like LangChain or AutoGen would route the artifacts between the agents sequentially.

- **`.github/workflows`**
  - `agent-playwright-e2e.yml`: The CI pipeline that triggers the Runner Agent and harvests the artifacts.

## 🧪 Example Showcase: Passing vs Failing

To demonstrate how the test harness works in reality, we have included two tests in the suite:

1. **`example.spec.ts` (PASS):** This test visits the Playwright homepage and asserts the title. The **Runner Agent** executes this and logs it as a success in `execution-report.json`.
2. **`ecommerce.spec.ts` (FAIL):** This test navigates through an e-commerce flow, but fails because the "Add to Cart" button isn't found in the current DOM state. 

### How the Harness Handles the Failure
When `ecommerce.spec.ts` fails, the **Debugger Agent** receives the logs. In a traditional framework, an agent might try to guess a new CSS selector like `.btn-primary` or `div > button:nth-child(2)` to make the test pass. 

**This harness explicitly forbids that.**

Because guessing selectors creates flaky tests, the Debugger Agent categorizes the issue as a `SELECTOR_FAILURE` and outputs `REQUIRES_REEXPLORATION`. The Orchestrator halts execution and sends the task back to the **Explorer Agent**, ensuring that the new button locator is captured from *real evidence* rather than hallucinated assumptions.

## 🏗️ Implementing this Architecture in New Projects

If you want to apply this Agent-Driven Test Harness architecture to a completely new project, follow these implementation steps:

1. **Establish the Policies:** Copy the `docs/` folder into your new project. Ensure your engineering team and AI agents are aligned on the `selector-policy.md` and `escalation-policy.md`.
2. **Implement the BasePage Gatekeeper:** Copy `playwright/utils/base-page.ts`. This is the most critical piece of code. It overrides locator methods to run regex checks against forbidden selectors (like XPath and dynamic IDs), throwing runtime errors if an agent tries to hallucinate bad locators.
3. **Set Up the Artifacts Directory:** Create `artifacts/exploration-reports` and `artifacts/build-reports`. Your agents must be strictly prompted to read and write from these directories rather than relying on conversational chat memory.
4. **Deploy the Agent Prompts:** Use the markdown files in `/agents` as system prompts for your chosen framework (AutoGen, LangChain, CrewAI). 
5. **Build an Orchestrator Script:** Create a Python or Node.js script that sequentially calls your LLMs, passing the JSON artifacts between them, and looping back to the Explorer Agent whenever the Debugger returns `REQUIRES_REEXPLORATION`.
